## Requerimientos funcionales

**RF01.** El sistema debe permitir que un usuario cree una cuenta en WiseTrip.

**RF02.** El sistema debe permitir que un usuario registrado inicie sesión para acceder a las funcionalidades de la plataforma.

**RF03.** El sistema debe permitir que el usuario seleccione uno de los destinos recomendados por WiseTrip.

**RF04.** El sistema debe generar un itinerario personalizado teniendo en cuenta las fechas del viaje, el presupuesto disponible para actividades y los intereses del usuario.

**RF05.** El sistema debe actualizar las actividades y opciones del itinerario cuando el usuario modifique las condiciones de planificación de su viaje.

**RF06.** El sistema debe permitir consultar opciones de alojamiento disponibles para el destino y las fechas seleccionadas.

**RF07.** El sistema debe integrar información de alojamiento proveniente de servicios externos para presentar diferentes opciones al usuario.

**RF08.** El sistema debe mostrar información relevante de cada opción de alojamiento, incluyendo su costo y disponibilidad cuando esta información se encuentre disponible.

**RF09.** El sistema debe permitir consultar opciones de transporte y movilidad relacionadas con el destino seleccionado.

**RF10.** El sistema debe presentar alternativas para que el usuario pueda desplazarse dentro del destino durante su viaje.

**RF11.** El sistema debe integrar información de proveedores de movilidad para apoyar la planificación de los desplazamientos del usuario.

**RF12.** El sistema debe permitir que el usuario ingrese el presupuesto que desea destinar a su viaje.

**RF13.** El sistema debe permitir que el usuario consulte el presupuesto establecido durante la planificación del viaje.

**RF14.** El sistema debe permitir que el usuario modifique el presupuesto de su viaje cuando lo considere necesario.

**RF15.** Si el usuario modifica únicamente su presupuesto y desea mantener el mismo destino, el sistema debe recalcular y mostrar recomendaciones actualizadas de acuerdo con el nuevo valor.

**RF16.** Si el usuario modifica su presupuesto y desea explorar nuevos destinos, el sistema debe permitir realizar una nueva búsqueda conservando sus intereses y preferencias previamente registrados.

**RF17.** El sistema debe mostrar la temperatura y las condiciones climáticas del destino antes y durante el viaje.

**RF18.** El sistema debe consultar posibles cambios relevantes en las condiciones climáticas entre 3 y 5 días antes del inicio del viaje y continuar actualizando esta información hasta su finalización.

**RF19.** El sistema debe identificar cuándo una condición climática pueda afectar alguna actividad incluida en el itinerario del usuario.

**RF20.** Cuando las condiciones climáticas puedan afectar una actividad del itinerario, el sistema debe recomendar actividades alternativas teniendo en cuenta el clima, los intereses y el presupuesto del usuario.

**RF21.** El sistema debe permitir que el usuario seleccione si desea recibir sus alertas mediante Telegram o correo electrónico.

**RF22.** El sistema debe generar alertas relacionadas con cambios importantes en el clima, situaciones que puedan afectar el viaje, cambios relacionados con el presupuesto o los gastos y nuevas recomendaciones.

**RF23.** El sistema debe enviar las alertas utilizando el canal de comunicación seleccionado previamente por el usuario.

**RF24.** El sistema debe solicitar al usuario información sobre sus gustos e intereses personales después de establecer el presupuesto y la información básica del viaje.

**RF25.** El sistema debe permitir que el usuario registre sus preferencias mediante preguntas de selección organizadas en categorías como aventura, cultura, gastronomía, naturaleza, vida nocturna, compras, descanso y economía.

**RF26.** El sistema debe recomendar destinos, lugares, actividades o planes teniendo en cuenta el presupuesto, las fechas, los intereses del usuario y las condiciones del viaje.

**RF27.** El sistema debe mostrar recomendaciones de destinos dentro del alcance establecido para WiseTrip en Latinoamérica.

**RF28.** El sistema debe permitir que el usuario solicite ayuda mediante un chat para resolver dudas relacionadas con el uso de WiseTrip o con la planificación de su viaje.

**RF29.** El sistema debe permitir que el usuario solicite soporte mediante correo electrónico.

**RF30.** Al finalizar el viaje, el sistema debe permitir que el usuario proporcione retroalimentación sobre su experiencia.

**RF31.** El sistema debe permitir que el usuario indique si las recomendaciones y el itinerario fueron de su agrado.

**RF32.** El sistema debe permitir que el usuario indique qué aspectos de su experiencia cambiaría o mejoraría.
